# API contract checks

The core TypeScript client is committed in `frontend/src/apiclient/autogenerated/`.
API changes must continue to include the result of `npm run generate:client` in
the same commit. No separate client package release or version bump is needed.
The `Check generated API client` workflow now enforces three complementary checks:

| Check | Detects |
| --- | --- |
| Regenerate and compare committed files | Missing, obsolete or stale generated client code |
| oasdiff against the base commit | Breaking changes to the declared HTTP request/response contract, even if the new client was regenerated |
| Schemathesis through Django WSGI | Response/schema mismatches and unexpected server errors in three selected authenticated GET operations |

## Backward compatibility

The comparison uses the PR target SHA, or the previous branch tip for a push to
`master`. It does not compare against the PR's own schema or a manually updated
baseline. The helper extracts tracked Python sources from that exact commit into
a temporary directory, generates the base schema, and removes the directory on
completion. It does not copy local environment files. Both schemas use
`DRFSpectacularExcludeCustomView`, matching core client generation; legacy v1,
custom views and external plugin endpoints are outside this contract.

The base is generated with the **current locked Python dependencies**. This is a
source compatibility check, not a recreation of the previous deployed runtime.
A generator or dependency update can affect both schemas equally. Such updates
still require review of the generated TypeScript diff and release compatibility.
Generated TypeScript symbol names and downstream consumer compilation are not
covered by an HTTP schema comparison.

The CLI is pinned to oasdiff v1.37.0 and fails on both WARN and ERR findings.
Missing history, schema generation failures (including Spectacular's per-view
errors), and invalid schemas fail the check. No upload/share feature is enabled.
Regression fixtures prove that operation/property deletion, request requiredness
and response type changes fail, while an optional request addition passes.

Run locally from the repository root:

```bash
uv sync --extra dev --locked
npm ci
go install github.com/oasdiff/oasdiff@v1.37.0
export PATH="$(go env GOPATH)/bin:$PATH"
PAGODA_LITE=1 npm run generate:client
uv run python -m unittest tools.tests.test_api_compatibility
uv run python tools/check_api_compatibility.py --base-ref upstream/master
```

Fetch the intended base first if it is not available locally. CI fetches the exact
event SHA and fails if it cannot resolve it. Do not fix a failure by replacing the
base with HEAD or disabling a check. Prefer additive optional fields, retain old
operations, or introduce a separately versioned endpoint when a break is needed.
Any policy change for an intentional break belongs in an explicit reviewed change.

## Runtime pilot

```bash
tools/lite.sh test airone.tests.test_api_contract
```

Schemathesis 4.14.1 is a locked development dependency. The pilot uses the existing
Django test runner and the Hypothesis Django integration; no pytest migration is
required. The explicit allowlist is:

- `GET /user/api/v2/me`
- `GET /entity/api/v2/`
- `GET /entity/api/v2/{id}/`

Each operation gets 12 bounded examples with seed `20261114`. Synthetic users,
tokens, entities and attributes are isolated by the test database. Calls go
through the real WSGI middleware and views in-process. Assertions require HTTP
200 and the expected nonempty fixture data, so a run of only authentication
errors or missing records cannot pass. Two mutation probes verify that malformed
response types and HTTP 500 responses are rejected.

This initial pilot generates positive cases, with existing IDs and bounded list
queries. It does not fuzz every query value, issue write/export requests, contact
a deployed server, or establish MySQL/Elasticsearch fidelity. Lite runs without
service containers; the core test matrix also discovers these tests on its real
service stack. Authorization correctness remains the responsibility of explicit
multi-user ACL tests. Expand the endpoint/input scope deliberately with fixtures
and reproducible failure cases.
